## What's in `capstone_claude/`

**Approach: A (three classes) plus a safety-net threshold.**
- The model can actively say "neither" instead of picking the least-bad of cat or dog.
- If the strongest cat/dog score is still weak, a threshold turns the answer into "neither". That threshold is tuned automatically on validation data.
- Approach B (cats vs dogs plus a threshold) is built as a real experiment (`python -m catdog train --two-class`). Its results become the evidence the brief asks for.

**How it's organised:**

| Layer | Where | What it does |
|---|---|---|
| Data | [catdog/data/](catdog/data/) | Mixes Oxford Pets, Caltech-101, Imagenette and your own photos. Each Caltech/Imagenette exclusion has a written reason, and a misspelled class name stops the run. |
| Model | [catdog/modeling/](catdog/modeling/) | Pretrained EfficientNetV2-B0. Training adds dim-lighting variations to mimic indoor phone photos. Training runs in two stages. |
| Inference | [catdog/inference/](catdog/inference/) | One image loader for any photo: 4000×3000, portrait, PNG transparency, HEIC, broken files (shown as an `error` row instead of crashing). |
| Metrics | [catdog/evaluation/](catdog/evaluation/) | One confusion-matrix module used by the CLI, the notebook and the web app, so their numbers always agree. |
| API | [catdog/server/](catdog/server/) | FastAPI service. It still starts without a model and explains what's missing. |
| UI | [web/](web/) | Three tabs, with light and dark themes and phone layout. **Classify:** drop a whole folder, see the three piles, grid or table view, CSV export, "copy table" in the brief's format. **Evaluate:** live confusion matrix with board-style fractions like `4/6`, and a list of mistakes to explain. **Model card:** data per source, the threshold chart, the Approach B evidence, and the exclusions. |

**Also included:**
- **Notebook:** [notebooks/capstone.ipynb](notebooks/capstone.ipynb) has a `TRAIN = False` switch, so *Restart and run all* never retrains. The assessment cell is section 6: change `FOLDER` and run.
- **Docs:** [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) covers the system design. [README.md](README.md) is written for the class repository.

I fixed several bugs found in testing:
- The validation split was the wrong size for small photo sets.
- Tall photos stretched the result cards.
- The page scrolled sideways on phones.
- The Model card printed a fixed "confident and wrong" verdict about Approach B regardless of the measured numbers. It now follows the data.

## 2. Why `Activate.ps1`?

`.ps1` is the file extension for **PowerShell scripts**. When Python creates a virtual environment on Windows, it puts several activate scripts in `.venv/Scripts/`, one for each kind of terminal:

| File | Terminal |
|---|---|
| `Activate.ps1` | PowerShell |
| `activate.bat` | Command Prompt (cmd) |
| `activate` (no extension) | **Git Bash** / bash ← the one you use |

I gave you the PowerShell one because your VS Code terminal was set to PowerShell. In Git Bash, use:

```bash
source .venv/Scripts/activate
```

On Mac or Linux the folder is called `.venv/bin/` instead of `.venv/Scripts/`. That difference matters for the Makefile (section 5).

**What "activate" does:** it puts `.venv/Scripts/` at the front of your PATH. After that, `python` and `pip` refer to the project's private copy, so packages install into this project only and not your whole computer.

---

## 3. Why two requirements files?

They list the Python packages the project needs, split by who needs them:

- **[requirements.txt](requirements.txt): runtime.** This is what you need to *use* the model: TensorFlow, NumPy, Pillow (opens images) and FastAPI/uvicorn (the web server). The [Dockerfile](Dockerfile) installs only this file, which keeps the deployed version small.
- **[requirements-dev.txt](requirements-dev.txt): development.** This is what you need to *build and test* the model. Its first line is `-r requirements.txt`, which means "include everything in the other file too". It then adds:
  - `tensorflow-datasets` to download Oxford Pets and Caltech
  - `matplotlib` for charts
  - `pytest` and `httpx` for tests

So on your own machine, install `requirements-dev.txt` and you get everything.

---

## 4. What `pyproject.toml` does

It is the standard **project settings file** for a Python project. `.toml` is a simple config format. [pyproject.toml](pyproject.toml) does four things:

- **`[project]`** gives the package's name (`catdog`), version, description, and minimum Python version (3.10).
- **`[project.scripts]`** means that if you install the project with `pip install -e .`, you get a command called `catdog`. You can then type `catdog predict folder` instead of `python -m catdog predict folder`.
- **`[tool.pytest.ini_options]`** tells pytest to look for tests in `tests/` and to print short output.
- **`[tool.ruff]`** is a setting for the ruff code-style checker (maximum line length).

You don't run this file. Tools like pip and pytest read it automatically.

---

## 5. What the `Makefile` does

A Makefile is a **list of shortcuts**. `make` is a program that reads it. Instead of typing a long command, you type `make test` and it runs `.venv/bin/python -m pytest` for you.

| Shortcut | Runs |
|---|---|
| `make install` | creates `.venv` and installs `requirements-dev.txt` |
| `make test` | runs the tests |
| `make serve` | starts the web page |
| `make predict FOLDER=...` | prints the table for a folder |
| `make evaluate` | confusion matrix on `data/holdout` |
| `make smoke` | tiny 50-image training run to check the pipeline works |
| `make train` / `make train-b` | full training for Approach A / Approach B |

**On your machine it won't work as-is**, for two reasons:
- Git Bash doesn't come with `make`.
- The file uses `.venv/bin/python` (the Mac/Linux path) and `python3`. On Windows those are `.venv/Scripts/python` and `python`.

Either run the commands directly as in section 1, or install make with `winget install ezwinports.make` and override the path each time: `make test PY=.venv/Scripts/python`.

### [catdog/](catdog/): the main Python code (the "package")
| File | Purpose |
|---|---|
| [\_\_init\_\_.py](catdog/__init__.py) | Marks the folder as a Python package and describes its layout. |
| [\_\_main\_\_.py](catdog/__main__.py) | Makes `python -m catdog ...` work by handing control to `cli.py`. |
| [cli.py](catdog/cli.py) | The command line: `predict`, `evaluate`, `train`, `serve`, `info`. |
| [config.py](catdog/config.py) | One place for settings (labels `cat/dog/neither`, image size, folder paths), so training and prediction always agree. |
| [preprocessing.py](catdog/preprocessing.py) | The single resize function. It **letterboxes**: shrinks the image and pads it to a square instead of stretching or cropping it. Training and prediction both use it, so any photo shape is handled the same way. |

**[catdog/data/](catdog/data/): where training images come from**
- [sources.py](catdog/data/sources.py) loads Oxford Pets (cat/dog), Caltech-101 and Imagenette (neither), and your photos in `data/own/`.
- [exclusions.py](catdog/data/exclusions.py) lists the Caltech/Imagenette classes removed from "neither" and **why**, for example `dalmatian` because it's a dog. The brief says "this is not busywork; it is the job."
- [pipeline.py](catdog/data/pipeline.py) mixes the sources, balances the three classes and splits them into training and validation sets.

**[catdog/modeling/](catdog/modeling/): the model itself**
- [model.py](catdog/modeling/model.py) defines EfficientNetV2-B0, pretrained on ImageNet (transfer learning), with a small 3-way output layer on top.
- [train.py](catdog/modeling/train.py) trains the model, measures it, tunes the "neither" threshold, then saves `model.keras`, `model_meta.json` and reports. With `--two-class` it runs the Approach B experiment instead.

**[catdog/inference/](catdog/inference/): using the trained model**
- [image_io.py](catdog/inference/image_io.py) opens *any* image: huge phone photos, rotated portraits, PNG, HEIC and so on. This covers the brief's "it handles any image" requirement.
- [predictor.py](catdog/inference/predictor.py) turns images into (label, confidence) rows. The CLI, the notebook and the web page all use this one file.

**[catdog/evaluation/](catdog/evaluation/): measuring it**
- [metrics.py](catdog/evaluation/metrics.py) builds the confusion matrix and computes accuracy, precision and recall, exactly what you'll calculate at the board.
- [threshold.py](catdog/evaluation/threshold.py) gives the evidence for your "neither" choice: it sweeps thresholds to show how well (or badly) Approach B works.

**[catdog/server/](catdog/server/): the web backend**
- [app.py](catdog/server/app.py) is the FastAPI server. It serves the web page plus `/api/predict`, `/api/evaluate`, and so on.
- [schemas.py](catdog/server/schemas.py) defines the shape of the data the API sends and receives.

### [web/](web/): the web page you see in the browser
- [index.html](web/index.html) is the page structure, with three tabs: Classify, Evaluate and Model card.
- [assets/styles.css](web/assets/styles.css) is how the page looks, including dark mode.
- [assets/app.js](web/assets/app.js) is the entry point. It switches tabs and checks whether the server has a model loaded.
- `assets/js/`:
  - `api.js` talks to the server.
  - `store.js` holds page state.
  - `util.js` has small helpers.
  - `views/` has one file per tab.

### [notebooks/capstone.ipynb](notebooks/capstone.ipynb)
The Colab notebook you train in and present from. It covers looking at the data, the Approach B evidence, training Approach A, and the hold-out confusion matrix. It also has the **assessment cell**, where you change one line (`FOLDER = ...`) on the day.

### [scripts/build_notebook.py](scripts/build_notebook.py)
This script generates the notebook from Python code, which makes changes easy to review. If you edit the notebook by hand in Colab instead, this file just goes out of date.

### [tests/](tests/)
Automated checks (`python -m pytest`):

### [data/](data/)

- **`data/holdout/{cat,dog,neither}/`**: a **separate** set of your photos the model **never trains on**. You run `evaluate` on these to get the confusion matrix you bring on the day.
